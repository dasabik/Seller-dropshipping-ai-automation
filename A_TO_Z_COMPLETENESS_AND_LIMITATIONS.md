- Setup, API, deployment, audit, manifest and upload guides.

## Checks performed for this release

- ZIP archive integrity check.
- JavaScript syntax check for the backend and AI service.
- Automated test suite: `node --test tests/static.test.js` (12 passed, 0 failed).
- Required file inventory and environment-variable reference review.

These checks verify archive structure, source syntax and selected static contracts. They are not the same as a live deployment test. A successful live test requires installing dependencies, a reachable PostgreSQL database, valid production secrets, and (for AI) an active Google AI key and model access.

## Important: what is not yet a complete live integration

The current code does **not** include verified end-to-end provider adapters for Flipkart, Amazon, Meesho, Shopify, IndiaMART/Roposo, Delhivery or Shiprocket. Environment-variable names or status indicators do not make those connections live. Actual integration requires provider-approved API access, OAuth/signature handling where applicable, API-specific request/response logic, webhook verification, retry/idempotency behavior and sandbox/production tests. Courier AWB creation and live tracking must not be treated as working until a provider response is received and verified. No fake orders, AWBs or tracking statuses are generated by this package.

The current product is therefore a deployable foundation with authentication/database APIs and Gemini-powered AI features, **not a fully completed production dropshipping automation system**. It would be misleading to guarantee that every feature works A-to-Z without credentials, a live environment and provider approvals.

## Local run (without Docker)

1. Install Node.js 20 or later and PostgreSQL.
2. Copy `.env.example` to `.env`; set a unique `JWT_SECRET` of at least 32 characters and valid PostgreSQL credentials.
3. Create the database named `seller_dropshipping_db` (or change the connection settings).
4. Run `npm install`.
5. Run `npm test`.
6. Run `npm start`, then open `http://localhost:5000`.
7. Set `GEMINI_API_KEY` only if you want the Gemini AI features. Keep `.env` private and never commit it.

## Docker run

1. Copy `.env.example` to `.env`.
2. Set `POSTGRES_PASSWORD` to a strong local database password and set `JWT_SECRET` to a unique random 32+ character value.
3. Run `docker compose up --build -d`.
4. Check `http://localhost:5000/api/health`.
5. Stop with `docker compose down`; keep the named `postgres_data` volume if you want to retain database data.
